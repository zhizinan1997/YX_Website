# 版本: v2.15

更新时间: 2026-03-30 11:14:00

- 后端安全边界全面收紧：移除项目根目录静态兜底暴露逻辑，前台静态资源改为白名单直出，内部运行目录与敏感路径不再可被公网直接访问。
- 内部文件访问策略升级：`/data/`、`/update_logs/`、源码目录、隐藏文件等请求统一返回 `404`，避免暴露运行态配置、日志与仓库结构。
- Admin 写接口统一加固：后台修改类 API 全部纳入登录态保护，未登录访问 `/api/*` 统一返回 `401`，避免匿名改写站点配置与上传资源。
- 后台 CSRF 防护统一化：所有后台写请求统一校验同源来源，缺失或伪造 `Origin/Referer` 的请求返回 `403`，并兼容 `宿主机 Nginx -> gateway -> website` 双层代理部署链路。
- 简历附件访问改为后台受控下载：关闭匿名公开简历直链，留言列表中的简历改为管理员登录后通过受控接口下载，并补充 `no-store` 缓存控制。
- 上传内容校验增强：后台图片上传改为校验真实文件签名，简历与知识库 PDF 上传补充文件头校验，降低伪装文件落盘风险。
- 生产启动要求收紧：生产环境必须显式提供 `SECRET_KEY` 与 `PUBLIC_BASE_URL`，首次部署还需提供 `ADMIN_PASSWORD_HASH` 或一次性 `ADMIN_PASSWORD` 完成超级管理员初始化。
- 弱默认值已废弃：不再允许依赖 `admin123`、占位 `SECRET_KEY` 等弱配置启动生产服务，HTTPS 域名场景下默认启用安全 Cookie 策略。
- Docker 镜像与仓库清理：`Dockerfile` 不再整包复制敏感运行态数据，`.gitignore`、`.dockerignore` 与 `.env.example` 已同步更新，降低敏感文件误提交与误打包风险。
- 运维文档同步更新：README 中的 `docker run` / `docker compose` 示例已改为安全版参数，明确双层代理部署所需环境变量与初始化步骤。
- 后台登录体验补强：Admin 前端新增统一 `401` 处理，登录态过期后会自动回到登录页，避免后台静默失败或停留在失效会话状态。
- 本版本为安全加固与部署规范升级版本，不改变现有 `Nginx -> gateway -> website` 部署拓扑；生产上线前需先完成新密钥与管理员凭据配置。
