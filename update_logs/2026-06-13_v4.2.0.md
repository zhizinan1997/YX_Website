# 版本: v4.2.0

更新时间: 2026-06-13 14:20:00

## 【新增】
- 网站数据后台新增 AI 报告后台生成任务：点击生成后立即返回任务状态，前端以进度条轮询展示排队、统计准备、AI 调用、保存完成等阶段，避免长时间按钮转圈造成“卡死”误解。
- AI 运营报告清单新增删除能力，并支持按周期保留上限自动清理，避免报告长期累积导致列表、下载和存储持续变慢。
- AI 报告 PDF 下载新增磁盘缓存和并发控制：同一份不可变报告首次生成后缓存 PDF 字节，后续下载直接回吐缓存文件。
- 知识库升级为“文本条目 + PDF 条目”两类独立管理：文本条目支持查看、编辑、删除；PDF 支持查看、下载、删除。
- 知识库新增增量上传能力：只输入文本、只上传 PDF、或文本与多个 PDF 同时提交都可追加保存，不再互相覆盖。
- 知识库新增旧版 `_manual_knowledge.txt` 懒迁移：首次读取时会迁移为一条文本知识条目，旧文件保留但不再作为主要写入目标。

## 【优化】
- AI 报告生成改为服务端互斥任务，同一时刻只允许一个生成任务运行，避免多个管理员或多标签页重复点击占满 Gunicorn 请求线程。
- AI 报告 AI 配置回退改为按配置组整体回退，避免 `api_key`、`api_base`、`model` 分别来自不同配置组导致 401/404 难排查。
- AI 报告请求增加 `max_tokens` 和 `temperature` 控制，并补充更清晰的状态与错误分类，降低模型超长输出和网络抖动带来的风险。
- AI 报告 Markdown 渲染补齐表格支持，后台预览与 PDF 侧展示保持一致。
- AI 报告清单每次打开都会刷新，避免多管理员协作时看到陈旧缓存。
- PDF 渲染链路增强日志：Chromium 失败、中文字体注册失败等降级原因会写入日志，不再静默掩盖真实问题。
- 知识库 PDF 同名上传会自动追加安全后缀，保留历史文件，避免增量上传覆盖旧文档。
- 知识库聚合读取保持兼容：客服回答仍通过 `load_knowledge_base()` 汇总文本条目与 PDF 提取内容。
- 一键 Docker 部署脚本帮助信息与 README 更新为单容器主站拓扑：新部署只启动 `yx-website`，不再要求 gateway 容器。

## 【修复】
- 修复 AI 调用在 Flask 请求线程内同步阻塞、且没有服务端并发保护的问题。
- 修复 AI 报告 JSONL 无限增长、无删除接口、全量读入排序导致长期运行后越来越慢的问题。
- 修复 AI 报告 PDF 每次下载都现场启动 Chromium、多人连点可能拉起多个 Chrome 实例的问题。
- 修复 AI 报告 Chromium 异常和中文字体异常被裸 `except` 静默吞掉的问题。
- 删除重复定义的 `build_site_analytics_report` 死代码，避免后续维护时改错版本。
- 修复非法 `anchor_date` 被静默回退为今天的问题；显式传入非法日期时会返回错误。
- 修复 AI 报告错误响应和成功响应携带完整统计上下文、导致报文过大且泄露不必要数据的问题。
- 修复没有 `site-reports` 权限的子管理员仍可 GET 报告清单和下载 PDF 的权限缺口。
- 修复旧知识库保存文本会覆盖全部历史文本、只上传 PDF 可能把文本清空的问题。
- 修复 PDF 知识库文件缺少 inline 查看接口的问题。

## 【兼容与迁移】
- 从 v4.1.0 升级推荐继续使用 `tools/dockerrun_upgrade.sh` 的“智能合并更新”。脚本会保留宿主机 `data/`、`pages/`、`cdn_assets/` 并按镜像基线合并新增默认文件。
- v4.1.0 或更早版本若仍存在 `yx-gateway` 容器，升级脚本会将其临时重命名为回滚备份；新 `yx-website` 验证成功后自动清理旧 gateway，不再启动新 gateway。
- 若新主站容器启动失败，脚本仍会回滚旧 `yx-website`，并在旧 gateway 存在时恢复旧 gateway，避免升级失败后站点直接中断。
- 旧宿主机 `update_logs/` 不再需要挂载；后台默认读取镜像内置 `update_logs`，全新重置或保留数据重置时会备份并清理旧遗留目录。
- 旧 `_manual_knowledge.txt` 会在知识库首次读取时迁移为单条文本知识，不会自动拆分，降低历史内容被误切的风险。
