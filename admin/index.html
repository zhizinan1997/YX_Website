CDN 加速设置

开启后主站访问 /cdn_assets/ 会返回 302 到 CDN 域名，客户端将直接从 CDN 拉取素材资源。

运维操作指南（上线/回滚）
  1. 准备阶段：确认 cdn_assets/ 已更新，CDN 域名证书正常，源站回源规则已指向当前网关。
  2. 填写域名：在“CDN 域名”中填写 https://cdn.example.com（不要带路径）。
  3. 连通检测：点击“测试连通性”，建议检测结果为 200 或 206。
  4. 启用加速：勾选“启用 CDN 加速”并保存，主站 /cdn_assets/* 将返回 302 到 CDN 域名。
  5. 上线验收：抽检首页、产品、新闻、关于页；重点验证大图、视频首帧与 Range 播放。
  6. 故障回滚：取消勾选“启用 CDN 加速”并保存，立即恢复主站本地资源链路。
  7. 变更留痕：记录操作人、时间、CDN 域名、测试结果和回滚动作，便于审计。
后端逻辑说明（给运维/开发）
  1. GET /api/cdn/settings：读取当前加速开关与域名（需登录）。
  2. POST /api/cdn/settings：保存 cdn_enabled、cdn_domain 到 data/config.json。
  3. 域名规范化：后端会规范为 http(s)://host[:port]，自动剔除路径和多余斜杠。
  4. POST /api/cdn/test：对样例资源执行 HEAD 与 Range GET 连通性检测。
  5. GET /cdn_assets/<path>：开启时返回 302 到 cdn_domain，关闭时回落到主站本地资源。
  6. /api/cdn/switch-header：保留兼容接口，用于读取当前开关状态。
仅填写域名，路径会自动拼接为 /cdn_assets/...

登录人机验证（Cloudflare Turnstile）

启用后，后台登录必须先通过 Turnstile 验证。无需变更你的域名解析，只需填写站点密钥。

Cloudflare 密钥申请全流程
  1. 登录 Cloudflare 控制台，进入 Turnstile（也可直接搜索 Turnstile）。
  2. 点击新增组件创建新部件，建议名称填 yx-admin-login。
  3. 在域名管理中加入你的后台域名（例如 admin.example.com），本地调试可加 localhost。
  4. 组件模式建议使用托管（默认），保存后会得到站点密钥和服务端密钥。
  5. 回到本页面：把站点密钥粘贴到“站点密钥（前端）”，把服务端密钥粘贴到“服务端密钥（后端）”。
  6. 勾选“启用 Turnstile 登录保护”，点击“保存设置”。
  7. 退出后台重新登录验证：登录页出现 Turnstile 即表示前端已接入；未先完成验证将无法登录。
注意：Turnstile 只是在登录页加载 Cloudflare 的验证脚本并由服务端验签，不需要变更你阿里云 DNS 解析记录。

推荐方式：整站备份（后台一键下载）

当前“下载备份 ZIP”已升级为尽可能完整的整站备份：会自动扫描项目根目录并打包站点文件， 同时排除缓存/开发目录（如 .git、node_modules、__pycache__、.venv 等）。

建议在关键改版前、上线前、以及每周至少执行一次整站备份。恢复时将按备份包内容覆盖对应文件。

1) 容器内执行备份（宿主机终端执行）

TS=$(date +%F_%H%M%S)
docker compose exec web sh -lc "cd /app && zip -r /tmp/yx_backup_${TS}.zip . -x '.git/*' 'node_modules/*' '__pycache__/*' '.venv/*' 'venv/*' '.pytest_cache/*' '.mypy_cache/*' '.ruff_cache/*' 'backups/*'"

2) 下载备份到宿主机（宿主机终端执行）

TS=$(date +%F_%H%M%S)
mkdir -p ./backups
FILE=$(docker compose exec web sh -lc "ls -t /tmp/yx_backup_*.zip | head -n1" | tr -d '\r')
docker compose cp web:${FILE} ./backups/

说明：如果你的服务名不是 web，请把命令中的 web 替换为实际服务名 （可用 docker compose ps 查看）。

完整备份下载

备份内容：尽可能整站（页面、静态资源、后台代码、数据文件、模板与工具脚本等），并自动排除缓存目录。 该 ZIP 可用于灾难恢复、服务器迁移或 Docker 重部署后快速回滚。

上传恢复（Docker 重部署后）

上传先前下载的 ZIP 备份包后将覆盖恢复对应目录。恢复成功后请重启服务并刷新后台页面。
